# Data dictionary

## _PandaDev Portfolio — PostgreSQL database_

Companion of the diagram [`schema.puml`](schema.puml): both files must be updated together. Only `users` exists today ([`db/init/01_users.sql`](../../db/init/01_users.sql)), the other tables are proposed.

---

## Conventions

| Notation          | Meaning                                                                                                |
|-------------------|--------------------------------------------------------------------------------------------------------|
| `L10n`            | `jsonb` holding one text per locale: `{"fr": "...", "en": "..."}`. `CHECK (col ? 'fr' AND col ? 'en')` |
| `IDENTITY`        | `integer GENERATED ALWAYS AS IDENTITY`, same as `users.id`                                             |
| `slug`            | URL identifier, `CHECK (slug ~ '^[a-z0-9]+(-[a-z0-9]+)*$')`, e.g. `pandadev-portfolio`                 |
| `position`        | Display order, ascending, default `0`                                                                  |
| Enumerated `text` | Stored in English, `CHECK (col IN (...))`. The website translates the value with `@nuxtjs/i18n`        |
| URLs              | Validated by the API (Pydantic `HttpUrl`), stored as `text`                                            |

## Table: `users`

People allowed to log in to the private area. **Existing table.**

| Field           | Type      | Constraint   | Required | Description                                                          |
|-----------------|-----------|--------------|----------|----------------------------------------------------------------------|
| `id`            | `integer` | PK, IDENTITY | ✅       | Unique identifier                                                    |
| `login`         | `text`    | UNIQUE       | ✅       | Login used on the login page                                         |
| `password_hash` | `text`    | —            | ✅       | bcrypt hash generated by pgcrypto (`crypt(..., gen_salt('bf', 12))`) |

> ℹ️ The password itself is never stored. bcrypt only uses the first 72 bytes of the password.

## Table: `profiles`

Public profile of a user. One profile at most per user.

| Field          | Type          | Constraint                             | Required | Description                                    |
|----------------|---------------|----------------------------------------|----------|------------------------------------------------|
| `user_id`      | `integer`     | PK, FK → `users.id`, ON DELETE CASCADE | ✅       | Owner of the profile                           |
| `slug`         | `text`        | UNIQUE, slug format                    | ✅       | Public URL of the profile, e.g. `/people/jdoe` |
| `display_name` | `text`        | —                                      | ✅       | Name shown on the website                      |
| `headline`     | `L10n`        | —                                      | ✅       | Short title, e.g. "Full-stack developer"       |
| `bio`          | `L10n`        | —                                      | ✅       | Presentation text (Markdown)                   |
| `location`     | `text`        | —                                      | ❌       | City or region, e.g. "Lyon, France"            |
| `avatar_id`    | `uuid`        | FK → `media.id`, ON DELETE SET NULL    | ❌       | Profile picture                                |
| `updated_at`   | `timestamptz` | DEFAULT `now()`                        | ✅       | Last change, updated by the API                |

## Association table: `user_technologies`

Technologies mastered by a user, with a self-assessed score.

| Field           | Type       | Constraint                                    | Required | Description                            |
|-----------------|------------|-----------------------------------------------|----------|----------------------------------------|
| `user_id`       | `integer`  | PK, FK → `users.id`, ON DELETE CASCADE        | ✅       | Person concerned                       |
| `technology_id` | `integer`  | PK, FK → `technologies.id`, ON DELETE CASCADE | ✅       | Mastered technology                    |
| `score`         | `smallint` | CHECK (`score BETWEEN 0 AND 100`)             | ✅       | Proficiency score from 0 to 100        |
| `level`         | `text`     | GENERATED ALWAYS AS (...) STORED              | ✅       | Level computed from `score`, read only |
| `position`      | `integer`  | DEFAULT `0`                                   | ✅       | Display order on the profile           |

> ℹ️ The composite primary key `(user_id, technology_id)` allows one score per technology and per user.
>
> ℹ️ `level` is computed by PostgreSQL, the API and the admin page cannot write it:
>
> | `score`  | `level`        | French label  |
> |----------|----------------|---------------|
> | 0 – 24   | `beginner`     | Novice        |
> | 25 – 49  | `intermediate` | Intermédiaire |
> | 50 – 74  | `advanced`     | Confirmé      |
> | 75 – 100 | `expert`       | Expert        |

## Table: `technologies`

Shared catalog of technologies, used by both the profiles (`user_technologies`) and the projects (`project_technologies`).

| Field      | Type      | Constraint         | Required | Description                                              |
|------------|-----------|--------------------|----------|----------------------------------------------------------|
| `id`       | `integer` | PK, IDENTITY       | ✅       | Unique identifier                                        |
| `name`     | `text`    | UNIQUE             | ✅       | Name, e.g. `Python`, `Nuxt`, `PostgreSQL`, `Claude Code` |
| `category` | `text`    | CHECK (enumerated) | ✅       | `language`, `framework`, `database`, `tool` or `ai`      |
| `icon`     | `text`    | —                  | ❌       | Iconify icon name, e.g. `i-simple-icons-python`          |

> ℹ️ `category` lets the website group the technologies and show AI tools apart from languages and frameworks.

## Table: `media`

Metadata of the uploaded files (images, CV in PDF). The file itself is stored outside the database.

| Field         | Type          | Constraint                         | Required | Description                                                 |
|---------------|---------------|------------------------------------|----------|-------------------------------------------------------------|
| `id`          | `uuid`        | PK, DEFAULT `uuidv7()`             | ✅       | Unique identifier, time-ordered (PostgreSQL 18)             |
| `owner_id`    | `integer`     | FK → `users.id`, ON DELETE CASCADE | ✅       | User who uploaded the file                                  |
| `storage_key` | `text`        | UNIQUE                             | ✅       | Path of the file in `uploads/` (later: key in an S3 bucket) |
| `mime_type`   | `text`        | CHECK (enumerated)                 | ✅       | `image/webp` or `application/pdf`                           |
| `width`       | `integer`     | CHECK (`width > 0`)                | ❌       | Width in pixels, `NULL` for a PDF                           |
| `height`      | `integer`     | CHECK (`height > 0`)               | ❌       | Height in pixels, `NULL` for a PDF                          |
| `size_bytes`  | `bigint`      | CHECK (`size_bytes > 0`)           | ✅       | File size                                                   |
| `alt`         | `L10n`        | —                                  | ✅       | Alternative text (accessibility) or document title          |
| `created_at`  | `timestamptz` | DEFAULT `now()`                    | ✅       | Upload date                                                 |

> ℹ️ On upload, the API checks the real file type, re-encodes images to WebP (Pillow) and removes their EXIF data (GPS position of phone pictures). The file name is the UUID, never the name sent by the user.

## Not stored in the database

| Data                                     | Location                             | Reason                                                    |
|------------------------------------------|--------------------------------------|-----------------------------------------------------------|
| Image and PDF files                      | `uploads/` volume (later: S3 bucket) | Keeps the database and its backups light, files cacheable |
| Interface texts (buttons, menus, labels) | `web/i18n/locales/*.json`            | Part of the code, versioned with it                       |
| Logo, favicon, design images             | `web/public/`                        | Static, change only with the design                       |
| Secrets (JWT key, database password)     | `.env` files                         | Never versioned, never in the database                    |
| JWT tokens and sessions                  | Sealed cookie (Nuxt session)         | Stateless authentication                                  |
| Contact messages                         | Not collected (`mailto:` link)       | Avoids spam handling and GDPR retention rules             |
