# Data dictionary

## _PandaDev Portfolio — PostgreSQL database_

Companion of the diagram [`schema.puml`](schema.puml): both files must be updated together. Only `users` exists today ([`db/init/01_users.sql`](../../db/init/01_users.sql)), the other tables are proposed.

---

## Conventions

| Notation          | Meaning                                                                                                                                                                                  |
|-------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `L10n`            | `jsonb` holding one text per locale: `{"fr": "...", "en": "..."}`. `CHECK (col ? 'fr')`: French is required, English is optional and the website falls back to French when it is missing |
| `IDENTITY`        | `integer GENERATED ALWAYS AS IDENTITY`, same as `users.idUser`                                                                                                                           |
| `slug`            | URL identifier, `CHECK (slug ~ '^[a-z0-9]+(-[a-z0-9]+)*$')`, e.g. `pandadev-portfolio`                                                                                                   |
| `position`        | Display order, ascending, default `0`                                                                                                                                                    |
| Enumerated `text` | Stored in English, `CHECK (col IN (...))`. The website translates the value with `@nuxtjs/i18n`                                                                                          |
| URLs              | Validated by the API (Pydantic `HttpUrl`), stored as `text`                                                                                                                              |

## Table: `users`

People allowed to log in to the private area. **Existing table.**

| Field                 | Type          | Constraint      | Required | Description                                                               |
|-----------------------|---------------|-----------------|----------|---------------------------------------------------------------------------|
| `idUser`              | `integer`     | PK, IDENTITY    | ✅       | Unique identifier                                                         |
| `login`               | `text`        | UNIQUE          | ✅       | Login used on the login page                                              |
| `password_hash`       | `text`        | —               | ✅       | bcrypt hash generated by pgcrypto (`crypt(..., gen_salt('bf', 12))`)      |
| `password_changed_at` | `timestamptz` | DEFAULT `now()` | ✅       | Last password change; the API rejects every token issued before this date |

> ℹ️ The password itself is never stored. bcrypt only uses the first 72 bytes of the password.
>
> ℹ️ `password_changed_at` is a column to add to the existing table (migration). After a password change, every other session is logged out, since JWT tokens cannot be revoked one by one.

## Table: `profiles`

Public profile of a user. One profile at most per user.

| Field                  | Type          | Constraint                                       | Required | Description                                                                         |
|------------------------|---------------|--------------------------------------------------|----------|-------------------------------------------------------------------------------------|
| `idUser`               | `integer`     | PK, FK → `users.idUser`, ON DELETE CASCADE       | ✅       | Owner of the profile                                                                |
| `slug`                 | `text`        | UNIQUE, slug format                              | ✅       | Public URL of the portfolio, e.g. `/portfolios/jdoe`                                |
| `is_public`            | `boolean`     | DEFAULT `false`                                  | ✅       | `false` = hidden portfolio, only visible to its member in the private area          |
| `display_name`         | `text`        | —                                                | ✅       | Name shown on the website                                                           |
| `headline`             | `L10n`        | —                                                | ✅       | Short title, e.g. "Full-stack developer"                                            |
| `bio`                  | `L10n`        | —                                                | ✅       | Presentation text (Markdown)                                                        |
| `location`             | `text`        | —                                                | ❌       | City or region, e.g. "Lyon, France"                                                 |
| `contact_email`        | `text`        | —                                                | ❌       | Contact address shown on the portfolio, validated by the API (Pydantic `EmailStr`)  |
| `contact_phone`        | `text`        | CHECK (`contact_phone ~ '^\+[1-9][0-9]{6,14}$'`) | ❌       | Contact phone number in international format (E.164), e.g. `+33612345678`           |
| `contact_form_enabled` | `boolean`     | DEFAULT `true`                                   | ✅       | Shows the contact form on the portfolio, when `contact_email` is set                |
| `availability`         | `text`        | CHECK (enumerated)                               | ❌       | `open_to_work`, `internship`, `apprenticeship` or `not_available`, shown as a badge |
| `now`                  | `L10n`        | —                                                | ❌       | What the person is working on or learning right now ("Now" section)                 |
| `now_updated_at`       | `timestamptz` | —                                                | ❌       | Last change of `now`, set by the API, shows how fresh the section is                |
| `updated_at`           | `timestamptz` | DEFAULT `now()`                                  | ✅       | Last change, updated by the API                                                     |

> ℹ️ `contact_email`, `contact_phone` and the CVs are published only when the member fills them in. They are never included in the page: the website fetches them from the API only when the visitor clicks to show or download them, so that spam bots cannot collect them from the HTML. The API limits these requests per visitor (e.g. 10 per minute). CVs are served by the API itself, never as public files of `uploads/`, because they usually contain the same contact details.
>
> ℹ️ A new profile is hidden (`is_public = false`). A hidden portfolio returns a 404 page to visitors and is left out of the header menu, the home page, the portfolio list, the sitemap, the search and the timeline. On group projects, the member's name is still shown, without a link to the portfolio.
>
> ℹ️ The contact form sends the message by email to `contact_email`, with the visitor's address as reply-to. The message is never stored in the database (see [Not stored in the database](#not-stored-in-the-database)). Turning the form off hides neither `contact_email` nor `contact_phone`.
>
> ℹ️ The profile picture and the CVs are linked through [`attaches`](#association-table-attaches).

## Association table: `attaches`

Files used by a profile: profile picture and CVs. One file at most per kind.

| Field     | Type      | Constraint                                    | Required | Description                                                                   |
|-----------|-----------|-----------------------------------------------|----------|-------------------------------------------------------------------------------|
| `idUser`  | `integer` | PK, FK → `profiles.idUser`, ON DELETE CASCADE | ✅       | Profile                                                                       |
| `idMedia` | `uuid`    | PK, FK → `media.idMedia`, ON DELETE CASCADE   | ✅       | File used by the profile                                                      |
| `kind`    | `text`    | CHECK (enumerated), UNIQUE (`idUser`, `kind`) | ✅       | `avatar` (profile picture), `cv_fr` or `cv_en` (CV in French or English, PDF) |

> ℹ️ The API checks that the file matches its kind: `image/webp` for `avatar`, `application/pdf` for `cv_fr` and `cv_en`.
>
> ℹ️ Deleting a media deletes its row here, so the profile simply loses its picture or CV. Deleting a profile deletes its rows, the media themselves are removed by the account deletion (see [`media`](#table-media)).

## Table: `social_links`

External links of a user, shown on their portfolio. All optional: a user can have no link at all, or several links of the same kind (e.g. two YouTube channels).

| Field          | Type      | Constraint                             | Required | Description                                                                          |
|----------------|-----------|----------------------------------------|----------|--------------------------------------------------------------------------------------|
| `idSocialLink` | `integer` | PK, IDENTITY                           | ✅       | Unique identifier                                                                    |
| `idUser`       | `integer` | FK → `users.idUser`, ON DELETE CASCADE | ✅       | Owner of the link                                                                    |
| `kind`         | `text`    | CHECK (enumerated)                     | ✅       | Picks the icon, see the list below                                                   |
| `url`          | `text`    | —                                      | ✅       | Link target                                                                          |
| `label`        | `text`    | —                                      | ❌       | Tells apart two links of the same kind, e.g. "Tutorials channel", shown as a tooltip |
| `position`     | `integer` | DEFAULT `0`                            | ✅       | Display order                                                                        |

> ℹ️ Link kinds, shared with [`experience_links`](#table-experience_links): `website`, `github`, `gitlab`, `linkedin`, `youtube`, `discord`, `instagram`, `x`, `artstation`, `behance`, `tryhackme`. A network missing from the list uses `website` with a `label`.

## Table: `experiences`

Background of a user: professional career, education and personal training.

| Field               | Type      | Constraint                             | Required | Description                                                                                                                      |
|---------------------|-----------|----------------------------------------|----------|----------------------------------------------------------------------------------------------------------------------------------|
| `idExperience`      | `integer` | PK, IDENTITY                           | ✅       | Unique identifier                                                                                                                |
| `idUser`            | `integer` | FK → `users.idUser`, ON DELETE CASCADE | ✅       | Person concerned                                                                                                                 |
| `kind`              | `text`    | CHECK (enumerated)                     | ✅       | `work` (job, internship, apprenticeship), `education` (degree) or `training` (personal training, e.g. TryHackMe, ANSSI MOOC)     |
| `organization`      | `text`    | —                                      | ✅       | Company, school, platform or training body                                                                                       |
| `title`             | `L10n`    | —                                      | ✅       | Job title (e.g. "Security engineer"), degree name, or course or certificate followed (e.g. "Learn Docker")                       |
| `employment_status` | `text`    | CHECK (enumerated), `work` only        | ❌       | `employee`, `supervisor` (agent de maîtrise) or `executive` (cadre)                                                              |
| `contract_type`     | `text`    | CHECK (enumerated), `work` only        | ❌       | `permanent` (CDI), `fixed_term` (CDD), `apprenticeship` (alternance), `internship` (stage), `temporary` (intérim) or `freelance` |
| `description`       | `L10n`    | —                                      | ✅       | Missions, results (Markdown)                                                                                                     |
| `location`          | `text`    | —                                      | ❌       | City, `NULL` for online training                                                                                                 |
| `start_on`          | `date`    | —                                      | ✅       | Start date                                                                                                                       |
| `end_on`            | `date`    | CHECK (`end_on >= start_on`)           | ❌       | End date, `NULL` = ongoing                                                                                                       |

> ℹ️ A single table for the three kinds: they share the same columns, and the timeline sorts the whole background with one query. The portfolio shows one section per `kind`.
>
> ℹ️ `employment_status` and `contract_type` only apply to `work`: `CHECK (kind = 'work' OR (employment_status IS NULL AND contract_type IS NULL))` rejects them for `education` and `training`. Both stay optional for `work`, and the website shows them as badges.
>
> ℹ️ The links of an experience (company website, YouTube channel, certificate…) are in [`experience_links`](#table-experience_links).

## Table: `experience_links`

Links of an experience, e.g. the website or YouTube channel of a company, the TryHackMe website, a certificate. All optional, several per kind allowed.

| Field              | Type      | Constraint                                         | Required | Description                                                                              |
|--------------------|-----------|----------------------------------------------------|----------|------------------------------------------------------------------------------------------|
| `idExperienceLink` | `integer` | PK, IDENTITY                                       | ✅       | Unique identifier                                                                        |
| `idExperience`     | `integer` | FK → `experiences.idExperience`, ON DELETE CASCADE | ✅       | Experience concerned                                                                     |
| `kind`             | `text`    | CHECK (enumerated)                                 | ✅       | Same kinds as [`social_links`](#table-social_links), plus `certificate` (picks the icon) |
| `url`              | `text`    | —                                                  | ✅       | Link target                                                                              |
| `label`            | `text`    | —                                                  | ❌       | Tells apart two links of the same kind, shown as a tooltip                               |
| `position`         | `integer` | DEFAULT `0`                                        | ✅       | Display order                                                                            |

> ℹ️ Kept apart from `social_links`: a company channel is not a link of the member, and the links of an experience are deleted with it.

Skills used during a job, or learned during a degree or a training.

| Field          | Type      | Constraint                                             | Required | Description           |
|----------------|-----------|--------------------------------------------------------|----------|-----------------------|
| `idExperience` | `integer` | PK, FK → `experiences.idExperience`, ON DELETE CASCADE | ✅       | Experience            |
| `idSkill`      | `integer` | PK, FK → `skills.idSkill`, ON DELETE CASCADE           | ✅       | Skill used or learned |

> ℹ️ A skill linked to an experience does not have to be in the member's `masters`: the background shows what was used, the skills section shows the self-assessed level.

## Association table: `masters`

Skills mastered by a user, with a self-assessed score.

| Field      | Type       | Constraint                                   | Required | Description                            |
|------------|------------|----------------------------------------------|----------|----------------------------------------|
| `idUser`   | `integer`  | PK, FK → `users.idUser`, ON DELETE CASCADE   | ✅       | Person concerned                       |
| `idSkill`  | `integer`  | PK, FK → `skills.idSkill`, ON DELETE CASCADE | ✅       | Mastered skill                         |
| `score`    | `smallint` | CHECK (`score BETWEEN 0 AND 100`)            | ✅       | Proficiency score from 0 to 100        |
| `level`    | `text`     | GENERATED ALWAYS AS (...) STORED             | ✅       | Level computed from `score`, read only |
| `position` | `integer`  | DEFAULT `0`                                  | ✅       | Display order on the profile           |

> ℹ️ The composite primary key `(idUser, idSkill)` allows one score per skill and per user.
>
> ℹ️ `level` is computed by PostgreSQL, the API and the admin page cannot write it:
>
> | `score`  | `level`        | French label  |
> |----------|----------------|---------------|
> | 0 – 24   | `beginner`     | Novice        |
> | 25 – 49  | `intermediate` | Intermédiaire |
> | 50 – 74  | `advanced`     | Confirmé      |
> | 75 – 100 | `expert`       | Expert        |

## Table: `skills`

Shared catalog of skills, technical or not, used by both the profiles (`masters`) and the projects (`uses`).

| Field      | Type      | Constraint                    | Required | Description                                                                    |
|------------|-----------|-------------------------------|----------|--------------------------------------------------------------------------------|
| `idSkill`  | `integer` | PK, IDENTITY                  | ✅       | Unique identifier                                                              |
| `name`     | `L10n`    | UNIQUE index on `name->>'fr'` | ✅       | Name, e.g. `{"fr": "Python"}`, `{"fr": "Travail en équipe", "en": "Teamwork"}` |
| `category` | `text`    | CHECK (enumerated)            | ✅       | One of the categories below                                                    |
| `icon`     | `text`    | —                             | ❌       | Iconify icon name, e.g. `i-simple-icons-python`, `i-lucide-camera`             |

> ℹ️ `category` lets the website group the skills, e.g. show AI tools apart from languages and frameworks:
>
> | `category`   | Group                    | Examples                                   |
> |--------------|--------------------------|--------------------------------------------|
> | `language`   | Programming language     | Python, TypeScript, SQL                    |
> | `framework`  | Framework or library     | Nuxt, FastAPI, Tailwind CSS                |
> | `database`   | Database                 | PostgreSQL, Redis                          |
> | `tool`       | Tool                     | Docker, Git, Figma                         |
> | `ai`         | AI tool                  | Claude Code                                |
> | `domain`     | Field of expertise       | Cybersecurity, pentest, networking         |
> | `method`     | Method or practice       | Scrum, TDD, CI/CD                          |
> | `design`     | Design                   | UI/UX design, graphic design               |
> | `art`        | Art and creation         | Drawing, photography, video editing, music |
> | `soft_skill` | Soft skill (savoir-être) | Teamwork, communication, autonomy          |
>
> ℹ️ `name` is translated because the non-technical skills are common words ("Travail en équipe" / "Teamwork"). Technical names like Python only fill `fr`, and the website falls back to it in English. The `category` labels are translated by the website.

## Association table: `works_on`

Authors of a project, with the role of each one. A project can have several authors. A co-author is first invited, and only becomes a member once they accept.

| Field       | Type      | Constraint                                       | Required | Description                                                   |
|-------------|-----------|--------------------------------------------------|----------|---------------------------------------------------------------|
| `idProject` | `integer` | PK, FK → `projects.idProject`, ON DELETE CASCADE | ✅       | Project                                                       |
| `idUser`    | `integer` | PK, FK → `users.idUser`, ON DELETE RESTRICT      | ✅       | Author                                                        |
| `status`    | `text`    | CHECK (enumerated), DEFAULT `'pending'`          | ✅       | `pending` (invitation not answered yet) or `accepted`         |
| `role`      | `L10n`    | —                                                | ❌       | What the author did on the project, e.g. "Back-end, database" |

> ℹ️ Invitations: the creator of a project is inserted as `accepted`. A co-author is inserted as `pending`, which the private area shows as a badge. Accepting sets `status` to `accepted`; declining deletes the row, so the member can be invited again. A `pending` member is not shown on the project page nor on their portfolio.
>
> ℹ️ Edit rights: every `accepted` member of a project can edit it, publish it and see its draft. Other users, `pending` members included, cannot. This rule is checked by the API, it needs no extra column.
>
> ℹ️ A project always keeps at least one `accepted` member. Three rules ensure it:
>
> - `ON DELETE RESTRICT` on `idUser`: an account cannot be deleted while it is a member of a project, or has a pending invitation (delete its invitations first);
> - a deferred constraint trigger (`DEFERRABLE INITIALLY DEFERRED`), checked at the end of the transaction, after a delete or update on `works_on` and after an insert on `projects`: it raises an error if a project still exists without any `accepted` member. Being deferred, it lets a whole project be deleted (its members go with it) and lets a project be created then given its creator in the same transaction;
> - the API refuses to remove the last member of a project, with a translated error message, before the database is reached.

## Table: `media`

Metadata of the uploaded files (images, CV in PDF). The file itself is stored outside the database.

| Field         | Type          | Constraint                              | Required | Description                                                    |
|---------------|---------------|-----------------------------------------|----------|----------------------------------------------------------------|
| `idMedia`     | `uuid`        | PK, DEFAULT `uuidv7()`                  | ✅       | Unique identifier, time-ordered (PostgreSQL 18)                |
| `idOwner`     | `integer`     | FK → `users.idUser`, ON DELETE SET NULL | ❌       | User who uploaded the file, `NULL` once the account is deleted |
| `storage_key` | `text`        | UNIQUE                                  | ✅       | Path of the file in `uploads/` (later: key in an S3 bucket)    |
| `mime_type`   | `text`        | CHECK (enumerated)                      | ✅       | `image/webp` or `application/pdf`                              |
| `width`       | `integer`     | CHECK (`width > 0`)                     | ❌       | Width in pixels, `NULL` for a PDF                              |
| `height`      | `integer`     | CHECK (`height > 0`)                    | ❌       | Height in pixels, `NULL` for a PDF                             |
| `size_bytes`  | `bigint`      | CHECK (`size_bytes > 0`)                | ✅       | File size                                                      |
| `alt`         | `L10n`        | —                                       | ✅       | Alternative text (accessibility) or document title             |
| `created_at`  | `timestamptz` | DEFAULT `now()`                         | ✅       | Upload date                                                    |

> ℹ️ On upload, the API checks the real file type, re-encodes images to WebP (Pillow) and removes their EXIF data (GPS position of phone pictures). The file name is the UUID, never the name sent by the user.
>
> ℹ️ Deleting an account keeps its media with `idOwner = NULL`, so that shared projects keep their images. The account deletion then removes the media that no project uses (avatar, CVs), files included, so that no personal data is kept.

## Not stored in the database

| Data                                     | Location                                                    | Reason                                                                                   |
|------------------------------------------|-------------------------------------------------------------|------------------------------------------------------------------------------------------|
| Image and PDF files                      | `uploads/` volume (later: S3 bucket)                        | Keeps the database and its backups light, files cacheable                                |
| Interface texts (buttons, menus, labels) | `web/i18n/locales/*.json`                                   | Part of the code, versioned with it                                                      |
| Logo, favicon, design images             | `web/public/`                                               | Static, change only with the design                                                      |
| Secrets (JWT key, database password)     | `.env` files                                                | Never versioned, never in the database                                                   |
| JWT tokens and sessions                  | Sealed cookie (Nuxt session)                                | Stateless authentication                                                                 |
| Contact messages                         | Sent by email to the member's `contact_email`, never stored | No GDPR retention in the database; bots are blocked by a hidden field and a per-IP limit |
